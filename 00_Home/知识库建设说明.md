# 知识库建设说明

## 建设目标
本库为 BMS 与车载硬件设计提供结构化的基本元器件知识，服务于器件选型、WCCA 分析、DFMEA 与后续 AI 辅助设计。

目标不是堆放厂商资料，而是把「参数定义、参数出处、工程用法、最坏情况取值」串成可追溯的链条：
- 通用规律与具体型号案例分离存放，避免新增型号时重复基础知识。
- 每个参数都带着测试条件与 Datasheet 出处，未溯源的数据一律标记。
- 结构固定、可被后续 Skill 直接检索，而不是靠自然语言重新理解。
- 追溯靠统一 ID，不靠文字描述：通用参数 → Datasheet 数据记录 → WCCA 映射行 → 分析目标与公式，每一跳都由 ID 完成对接。

## 目录约定
- 一级目录按器件大类划分，编号前缀决定排序；器件类别在二级目录，每个类别一个入口文档。
- 00_Home 放导航与索引；01_Fundamentals 放跨器件的基础方法；08_WCCA_Knowledge 放分析方法；09_Templates 放模板；99_Management 放项目管理文档。
- 07_Datasheet_Cases 按器件子目录存放具体型号案例，与本阶段只建 Resistors / Capacitors / MOSFET 三个子目录。
- 项目管理与原始需求文件放 99_Management/00_项目文件，不参与知识检索。
- 新增目录必须先经确认再建，不临时加目录。

## 命名与链接约定
- 文件名使用中文全角标点与下划线，不用空格、不用英文括号；器件类别入口文档统一以「器件名_索引」命名。
- 全库文件名唯一；双链统一用双方括号包裹文件名，不带路径、不带扩展名。
- 禁止链接到不存在的文档；删除文档前先清理所有入链。
- 除首页外，每个文档至少被一个其他文档链接，避免出现孤立文档。
- 交叉引用只指向稳定文档（索引、模板、方法文档），不指向临时草稿。

## Frontmatter 约定
每个 Markdown 文件以 YAML Frontmatter 开头，八个字段为必填：

| 字段 | 取值说明 |
|---|---|
| type | home / index / fundamentals / wcca / template / management |
| category | passive / semiconductor / timing / logic / analog / cross |
| status | planned / draft / reviewed / deprecated |
| version | 文档版本号，Phase 0 统一起始版本 |
| wcca_relevant | 是否参与最坏情况分析，true / false |
| tags | 英文标签列表，便于检索与 Skill 调用 |
| created | 建档日期 |
| updated | 最近修改日期 |

规则：
- 骨架未填充内容的文档一律 status: planned；填完待评审为 draft；评审通过为 reviewed；作废为 deprecated。
- 修改内容必须同步更新 updated 字段，并按 [[更新记录]] 的约定登记。

### 统一 ID 字段

三类文档在上述八个基础字段之外必须追加统一 ID 字段，取值与格式见 [[元器件知识库统一ID规范]]：

| 字段 | 必填文档类型 | 取值说明 |
|---|---|---|
| component_class_id | 器件类别入口文档、Datasheet 案例文档、WCCA 映射文档 | 器件类别 ID，取自 ID 规范的类别注册表，与入口文档一一对应 |
| id_schema_version | 同上 | 本文档所遵循的 ID 规范版本号；规范升主版本时必须复核并同步 |

规则：
- 类别 ID 一经分配，不因文档改名、目录移动或版本更新而改变；废弃类别的 ID 不重新分配。
- 案例文档与 WCCA 文档正文中的型号、Datasheet、数据记录、公式、分析目标、修正模型一律以 ID 引用，不写自由文本编号。
- 新增器件类别时，先在本说明对应的目录建档，再在 ID 规范的类别注册表登记类别 ID，两处必须同时完成。

## 写作与数据纪律
任何具体参数值必须能回答「从哪来、什么条件、是否保证值」三个问题。全库只使用六类取值，写文档时逐条标注：

1. **保证值**：原厂在指定测试条件下承诺的极值，可直接用于 WCCA，须同时登记测试条件与出处。
2. **典型值**：原厂给出的典型表现，不构成保证，不得当作极值使用，只能做敏感性分析。
3. **读图值**：从原厂曲线读出的数值，须登记读点位置与读取误差，不能直接当作保证边界。
4. **计算值**：由公式与已知量推导得出，必须同时给出公式 ID、输入参数 ID 与计算过程。
5. **工程假设值**：资料不足时的临时假设，必须写明假设理由与适用边界，并有评审批准记录，同时登记 [[待确认问题]]。
6. **待确认值**：存在争议或资料缺失的条目，只标记不填数，登记责任人与确认依据。

六类之外的表述（如「设计参考值」「大概」「参考附近数值」）不得使用；历史文档中的旧表述按 [[元器件知识库数据分类与来源规则]] 的别名登记逐条拆分改写，不做机械替换。

### 测试条件与出处

- 参数值与测试条件必须成对出现，不允许孤立数值。测试条件按七要素记录：温度、输入电压、输出电压、电流或负载、频率、偏压、其他必要条件；缺项写「未注明」，不得留空。
- 每个数值都要能指到 Datasheet 页码与表号或曲线号；只写页码不够。
- 不擅自换算或插值：换算须保留原始值与原始单位并注明依据，插值结果按计算值处理。
- 曲线读数、典型值不得升级为保证值；Absolute Maximum Ratings 不得当作正常工作条件。

### 单一事实来源与 ID 引用

- 同一参数事实只在一处维护：参数定义在器件类别入口文档登记，原始数值在案例文档以数据记录 ID 登记，WCCA 只做映射与计算，不重复维护同一参数事实。
- 下游文档只引用 ID；发现两处不一致时以登记处为准并回改引用方。
- 派生结论必须能沿 ID 链回溯到页码与表号，无法回溯的结论不得写入正式分析。

写作纪律：
- 不得编造未在 Datasheet 中出现的数值；未提供即写「未提供」。
- 不得把规范或验收标准原文抄进知识文档充作内容。
- 骨架阶段只写填写指引与结构，不写入任何具体量值。
- 器件通用文档不掺入具体型号数据；型号数据只出现在案例文档。
- 模板中的示例行必须带「示例」或「占位」或「非真实」标记，禁止把示例数值当作真实参数引用。
