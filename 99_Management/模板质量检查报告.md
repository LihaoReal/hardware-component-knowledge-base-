# 模板质量检查报告

## 报告范围与口径

- 检查对象：模板体系 V1.0 修订的 5 个被修改文件与 7 个新建文件
- 检查时机：修订完成后、提交验收前
- 检查人：Agent B（执行与自检）
- 判定口径：每条验收要求给出结论（PASS 或 FAIL）与可复现的检查方法；结论只覆盖本条要求的检查范围
- 编号说明：验收要求 1 至验收要求 10 的条号沿用 A 侧修订规范对任务书第十节十条验收要求的编号；同一条要求对应的 A 侧验收标准编号在括号内标注，便于双向核对。若条文措辞与任务书原文有出入，以任务书原文为准。

## 逐条检查结论

### 验收要求 1（对应 AC-01）：三个模板的二级标题结构保持不变

- 检查方法：执行 `python tasks/TASK-009/inputs/verify_templates.py --check AC-01`，用二级标题正则提取三个模板的标题列表，与修订前基线做顺序敏感的列表相等比较。
- 实测结果：元器件通用知识模板 9 个、Datasheet案例模板 8 个、WCCA参数映射模板 8 个，与修订前逐字逐序一致。
- 结论：PASS

### 验收要求 2（对应 AC-02）：统一 ID 规范完整

- 检查方法：`verify_templates.py --check AC-02` 断言 8 类 ID 的类型名与示例全部出现；断言 19 个器件类别入口文档文件名全部出现；统计注册表数据行数与下限比较；对不变性条款关键词做包含判定。
- 实测结果：8 类类型名与示例全部命中；19 个入口文档全部覆盖；注册表数据行 19 行（下限 19）；「改名」「移动」「重新分配」三项条款关键词齐备。
- 结论：PASS

### 验收要求 3（对应 AC-03）：三个模板的 ID 规则完全一致

- 检查方法：`verify_templates.py --check AC-03` 用统一正则扫描三模板中的全部 ID 串，按 8 类模式归类（长前缀优先），再检查每个模板必需 ID 类型覆盖情况与同类前缀写法一致性。
- 实测结果：无法归类的 ID 串 0 个；通用模板覆盖参数/公式/分析目标 3 类，案例模板覆盖参数/型号/Datasheet/数据记录 4 类，WCCA 模板覆盖 6 类；同一 ID 类型在三模板中的前缀写法一致（示例统一使用电阻类别 RES 前缀）。
- 结论：PASS

### 验收要求 4（对应 AC-04）：通用知识模板修订到位

- 检查方法：`verify_templates.py --check AC-04` 定位「参数体系」章节内全部表头，断言存在同时含 9 个必需列（参数 ID、英文名称、中文名称、符号、单位、参数定义、物理意义、影响因素、工程应用场景）的表；断言「常见失效模式」表含「相关参数 ID」列；逐组断言必需表述命中；断言旧表述不出现。另以人工核对确认 Frontmatter 新增字段、N/A 规则、四层参数性质、参数相关性与耦合、WCCA 关联四项登记要求均已落地。
- 实测结果：参数体系表 9 列齐备；失败模式表含相关参数 ID；8 组必需表述全部命中；旧表述「设计参考值」出现 0 次。
- 结论：PASS

### 验收要求 5（对应 AC-05）：Datasheet 案例模板修订到位

- 检查方法：`verify_templates.py --check AC-05` 对「关键参数提取表」「曲线与图表摘录」「参数缺口与待确认」三张表断言必需列；逐组断言 12 组必需表述命中；断言旧表述不出现。
- 实测结果：参数提取表 11 列齐备（含数据记录 ID、参数 ID、参数性质）；曲线表 5 项新增列齐备；缺口表责任人/确认依据/确认日期齐备；12 组必需表述全部命中；旧表述出现 0 次。
- 结论：PASS

### 验收要求 6（对应 AC-06）：WCCA 参数映射模板修订到位

- 检查方法：`verify_templates.py --check AC-06` 对「参数映射总表」断言 8 个新增列、对「计算公式」断言 5 个必需列；逐组断言 10 组必需表述命中；断言旧表述不出现。
- 实测结果：映射总表由 8 列扩为 16 列，8 个新增列齐备且原 8 列保留；公式表含公式 ID、输入参数 ID、输出参数 ID、适用条件、判定依据；10 组必需表述全部命中；旧表述出现 0 次。
- 结论：PASS

### 验收要求 7（对应 AC-07）：六类取值与测试条件规则统一

- 检查方法：`verify_templates.py --check AC-07` 对三模板与《元器件知识库数据分类与来源规则》逐个断言六类取值词全部出现；对后者断言测试条件七要素全部出现；对三模板断言旧表述不出现。
- 实测结果：四个文件的六类取值全部齐备（保证值、典型值、读图值、计算值、工程假设值、待确认值）；测试条件七要素（温度、输入电压、输出电压、电流或负载、频率、偏压、其他必要条件）齐备；三模板旧表述出现 0 次。
- 结论：PASS

### 验收要求 8（对应 AC-08）：单一事实来源与结构化预留落地

- 检查方法：`verify_templates.py --check AC-08` 对三个模板与两份规范共 5 个文件断言单一事实来源类条款出现；对《统一 ID 规范》统计「ID 类型 → 唯一登记位置」表行数。
- 实测结果：5 个文件均声明不重复维护同一事实/只引用 ID；登记位置表 8 行，覆盖 8 类 ID 的登记归属；三模板均写明映射与公式只引用 ID、不重复维护。
- 结论：PASS

### 验收要求 9（对应 AC-09）：修订记录与质量检查报告齐备

- 检查方法：`verify_templates.py --check AC-09` 对《模板修订记录》做五要素包含判定，并从修订基线读取三个模板的修订前哈希逐个断言出现；对《模板质量检查报告》用正则提取验收要求编号并统计结论标记数量。
- 实测结果：修订前 / SHA-256 / 回滚 / 快照 / 未改动 五要素齐备；三个修订前 SHA-256 原样登记且与基线一致；本报告覆盖验收要求 1 至 10 全部十条，结论标记数量满足下限。
- 结论：PASS

### 验收要求 10（对应 AC-10、AC-11）：修订边界合规且无编造数值

- 检查方法：先核对修订基线清单自身 SHA-256 锚点，再执行 `python tasks/TASK-009/inputs/gen_revision_baseline.py --check`，由脚本逐项比对：库内基线文件哈希、授权修改文件是否真的变化、新增文件集合是否为白名单 7 个、三份快照是否逐字节等于修订前原件、新增文件扩展名是否越界、框架受保护文件与 git 状态、任务目录合法性。另执行 `verify_templates.py --check AC-10b` 逐行扫描含单位数值的行是否带示例/占位/非真实标记。
- 实测结果：边界复核脚本退出码 0，仅 5 个授权文件变更、新增恰为 7 个、快照逐字节一致、无越界扩展名；带单位数值的行标注检查违规 0 处；反例注入验证见自检报告的边界条件一节。
- 结论：PASS
